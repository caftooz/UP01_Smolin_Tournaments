# Платформа организации киберспортивных турниров

Учебная практика УП.01.01, ПМ.01 «Разработка модулей программного обеспечения для компьютерных систем»,
МДК.01.02. Выполнил: Смолин А. С., группа 4ИСИП-423. Руководитель: Т.Г. Аксёнова.

Настольное WPF-приложение для клуба «Cyber Nexus». Игроки и организаторы смотрят каталог турниров
с поиском, фильтрами и сортировкой. Администратор ведёт турниры, пользователей и справочники,
строит диаграммы и выгружает отчёты в Word, PDF и Excel.

## Возможности

| Роль | Что доступно |
| --- | --- |
| Гость | Вход, регистрация, смена пароля, смена темы |
| Пользователь (Игрок, Капитан, Судья, Организатор) | Каталог турниров: просмотр, поиск, фильтры по дисциплине и статусу, «только онлайн», сортировка |
| Администратор | Всё, что у пользователя, а также: добавление, изменение и удаление записей в восьми разделах (турниры, пользователи, дисциплины, форматы, статусы турниров, площадки, типы нарушений, статусы матчей); диаграмма; экспорт в .docx, .pdf и .xlsx |

Общее для всех страниц:

- пароли хранятся как SHA-256 от соли и пароля (`PasswordSalt`, `PasswordHash`);
- после трёх неверных попыток входа появляется капча, копировать её нельзя;
- ошибки ввода показываются одним сообщением; у полей есть маски ввода, ограничения длины
  и диапазоны чисел;
- у полей есть плейсхолдеры и всплывающие подсказки;
- удаление и выход требуют подтверждения; удаление турнира каскадно удаляет связанные записи,
  и перед удалением программа показывает, сколько их;
- светлая и тёмная темы, выбор сохраняется после перезапуска;
- заголовок окна меняется вместе со страницей: «Турниры — Авторизация», «Турниры — Таблица: площадки»;
- действия пользователей записываются в журнал `AuditLog`.

## Технологии

- C#, WPF, .NET Framework 4.8 (C# 7.3), Visual Studio 2026
- Microsoft SQL Server, Entity Framework 6 (Database First, `Model1.edmx`)
- Microsoft Office Interop (Word, Excel) — экспорт отчётов
- System.Windows.Forms.DataVisualization в `WindowsFormsHost` — диаграмма

## Запуск

Нужны Windows, Visual Studio с рабочей нагрузкой «Разработка классических приложений .NET»,
SQL Server (подойдёт Express) и SQL Server Management Studio. Для экспорта отчётов —
установленные Microsoft Word и Excel.

1. Откройте `db/DB_Smolin_Tournaments.sql` в SSMS и выполните его. Скрипт создаёт базу
   `DB_Smolin_Tournaments` со всеми таблицами, связями, ограничениями и тестовыми данными.
2. Откройте решение `UP01_Smolin_Tournaments.slnx` в Visual Studio.
3. В `App.config` в строке подключения `DB_Smolin_TournamentsEntities` замените
   `data source=DESKTOP-ALEX\SQLEXPRESS` на имя своего сервера.
4. Восстановите пакеты NuGet (Entity Framework 6.2), если Visual Studio не сделала этого сама,
   соберите проект и запустите (F5).

## База данных

27 таблиц по ER-модели курсового проекта. Приложение работает с таблицами `Tournaments`, `Users`,
`Roles`, `Disciplines`, `TournamentFormats`, `TournamentStatuses`, `Venues`, `ViolationTypes`,
`MatchStatuses` и пишет журнал в `AuditLog`. Команды, заявки, матчи и статистика заполнены
тестовыми данными и участвуют в каскадном удалении.

Каскадное удаление настроено в самой базе правилами `ON DELETE`:

| Удаляется | Вместе с ним удаляются | Ссылка очищается |
| --- | --- | --- |
| Турнир | заявки, участники, призовые места, спонсорские договоры, стадии → группы, матчи → карты матчей → статистика игроков | нарушения в удалённых матчах |
| Дисциплина | карты дисциплины | — |
| Пользователь | уведомления | записи журнала действий |

Остальные связи запрещают удаление используемой записи: например, нельзя удалить дисциплину,
по которой есть турниры.

## Устройство приложения

Одно окно `MainWindow`: сверху панель с логотипом и кнопками «Назад», «Сменить тему», «Выйти»
и «Сменить пароль», в центре `Frame` со страницами, внизу пользователь и часы.

Страницы администратора для таблиц не пишутся вручную. Одна страница `TablePage` и одна форма
`EditPage` работают с любой сущностью. Столбцы, поля, типы, обязательность, длина строк, ключи
и связи берутся из модели Entity Framework (`EntityInfo`). Русские подписи, диапазоны чисел,
шаблоны и маски задаются в одном словаре `UiMetadata`. Особые правила турнира и пользователя
вынесены в `TournamentRules` и `UserRules`. Сведения о каскадном удалении программа читает
из `sys.foreign_keys` (`DbSchema`).

Чтобы подключить ещё одну таблицу, достаточно добавить кнопку в `Pages/AdminPage.xaml`:

```xml
<Button Content="Спонсоры" Tag="{x:Type m:Sponsor}" ToolTip="Справочник спонсоров" Click="Section_Click"/>
```

и при желании русские названия таблицы и её полей в `Helpers/Crud/UiMetadata.cs`.

│   ├── CaptchaHelper.cs       генерация капчи
│   ├── PasswordHelper.cs      соль, SHA-256, правила пароля
│   ├── Msg.cs                 окна сообщений
│   ├── Db.cs                  контекст БД и сохранение с понятными ошибками
│   ├── FormValidator.cs       сбор ошибок ввода в одно сообщение
│   ├── InputMask.cs, Field.cs маски ввода и плейсхолдеры
│   ├── Session.cs             роли и проверка прав
│   ├── Audit.cs               журнал действий

│   └── Crud/                  автогенерация таблиц и форм администратора
├── Pages/
│   ├── AuthPage               авторизация и капча
│   ├── RegPage                регистрация
│   ├── ChangePassPage         смена пароля
│   ├── UserPage               каталог турниров
│   ├── AdminPage              панель администратора
│   ├── TablePage, EditPage    универсальные таблица и форма
│   └── DiagrammPage           диаграмма и экспорт в Word, PDF, Excel
├── Properties/                настройки, в том числе выбранная тема (Theme)
├── db/                        скрипт базы данных с тестовыми данными
└── res/                       иконка, логотип, шрифт Open Sans
